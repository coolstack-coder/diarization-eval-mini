Voice Arena take-home · Q1 one-pager · Anmol Adwani

A diarization leaderboard that helps people choose, not just rank

The eval in one paragraph

The board ranks "who spoke when" systems for teams building meeting tools, call analytics, medical scribes and subtitles. The question it answers is "which system is best for my kind of audio, and is the difference real?" There are 18 systems at launch: open models such as pyannote community-1, NVIDIA Nemotron-3-Diarization and DiariZen; diarization APIs such as pyannoteAI; and speech-to-text APIs with speaker labels from AssemblyAI, Deepgram, Speechmatics, AWS, Google, Azure, ElevenLabs, Rev, Gladia and OpenAI. All of them run on a hidden, newly recorded 52-hour test set covering 7 domains.

Core setup

Test data~400 recordings, ~700 speakers, 7 domains (meetings, video calls, 8 kHz phone, clinical, broadcast, noisy field, code-switch), accent-balanced English plus 4 other languages
ReferenceClose-talk mics plus forced alignment (≈20 ms boundaries), human correction, 15% double-annotated; the human agreement floor is published
Primary metricDER, pooled per domain, then averaged over domains with equal weight
SettingsNo collar · overlap scored · speaker count not given · system's own VAD
Also shownMiss / FA / confusion, JER, overlap DER, speaker-count error, short-turn recall, cpWER, speed, $/hour
SignificancePaired bootstrap over recordings, stratified by domain; systems whose gap isn't real share a tier

The 4 choices that matter most

  • Collar 0. The reference is machine-aligned, so it doesn't need forgiving. In my pilot, a 0.25 s collar deleted 22% of scored speech, mostly the hard turn changes.
  • Overlap scored. It was 17% of speech in my pilot meetings. STT APIs can't output it, so the board shows that penalty separately instead of hiding it.
  • Blind speaker count ranks; the hinted run sits beside it. Users rarely know the count. In my pilot, giving the count cut DER by up to 48 points on default settings.
  • Tiers, not ranks. A 0.3-point gap inside overlapping confidence intervals is not a win. The procurement reader is the one who can least tell.

Pilot I ran (3 AMI meetings × 2 mics × 3 open pipelines, 10 min each)

SetupAMI IS1009a, TS3003a, EN2002b · headset mix vs far-field mic · sherpa-onnx builds of A = pyannote-seg + WeSpeaker, B = Reverb + WeSpeaker, C = pyannote-seg + TitaNet · 54 runs scored with pyannote.metrics · code: github.com/coolstack-coder/diarization-eval-mini
Defaults flip rankingsDefault threshold: C guessed 30–59 speakers for 4-person meetings, and A beat C (58.3 vs 61.3 DER). After tuning on one held-out meeting, C beat A by 16 points (25.9 vs 42.4). → every open system gets the same dev-set tuning.

Mics change the gapWith k=4, A ≈ C on close-talk audio (30.5 vs 27.8, a tie), but on far-field A 54.5 vs C 34.9. → far-field and phone are separate domains.
Settings matterThe same output scores 27.8 strict, 21.8 with a collar, 16.1 with collar + skip-overlap. Overlap is 17% of speech.

Fairness rules, briefly

Same audio bytes for every system, phone audio left at 8 kHz · APIs at defaults, open systems all tuned on the public dev set with one fixed procedure, plus at most one vendor config tuned on dev · a single open converter turns word labels into segments · a failed file counts as 100% miss and is shown publicly · version string and run date shown on every row · zero-retention APIs and quarterly test rotation · offline, streaming and transcript tracks never mixed in one ranking.

Main takeaway. A diarization score means little without its settings, domain and confidence interval. In one hour of public audio, defaults flipped a ranking, the scoring settings changed DER by 1.7×, and one-speaker output got a low DER. So the board ranks on strict, blind, domain-balanced DER, groups statistical ties into tiers, and always shows JER, speaker-count error and the worst domain alongside.
